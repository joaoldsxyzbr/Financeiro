# AGENTS.md — Financeiro

## Regras permanentes
1. **Tecnologia:** site em HTML, CSS, JavaScript puro (ES Modules) e SQL. Backend Cloudflare Workers, banco Cloudflare D1. Não usar React, Vite, Vue ou TypeScript.
2. **D1 exclusivo:** usar apenas o banco `financeiro` (ID `66379719-dc22-4e1f-9645-ae5a52ff43af`), binding `DB`. Nunca tocar os antigos bancos de gastos ou ponto sem pedido explícito.
3. **Tabela obrigatória:** `registros`, com sete colunas nesta ordem: `data` (AAAA-MM), `tipo` (`entrada` ou `saida`), `descricao`, `valor` (centavos inteiros positivos), `categoria`, `status` (`pendente` ou `pago`) e `usuario_id` (FK obrigatória para `usuarios.id`). Identificar linhas pelo `rowid` implícito. Nunca inferir o tipo pelo sinal do valor.
4. **Interface:** painel financeiro responsivo, profissional, simples e claro, em português, com filtro mensal, lançamentos e resumo de receitas/despesas. Sem armazenar dia do mês ou parcelas.
5. **Segurança:** exigir secret `FINANCEIRO_API_TOKEN` com mínimo de 32 caracteres para a API real; nunca expor segredos ou dados privados sem autenticação. Usar SQL parametrizado e validações server-side. Não salvar token no armazenamento do navegador.
6. **Demonstração:** dados fictícios apenas em memória, rotulados como demo; nunca gravar testes no D1.
7. **Código:** organização leve em `public/`, `src/` e `migrations/`, sem dependências desnecessárias, testes antes de publicar.
8. **Deploy:** configurar binding do D1 neste repositório. Não publicar nem criar secret sem autorização/contexto suficiente.
9. **Usuários:** a tabela `usuarios` contém somente `id`, `nome`, `usuario` (único, sem diferenciar maiúsculas/minúsculas) e `senha_hash`. `usuario` é o identificador de login (3 a 50 caracteres, sem espaços nas pontas); **não há coluna `email`, `ativo` nem `criado_em`**. Nunca salvar senhas em texto puro. O código já implementa login individual com hash salgado e sessões assinadas. O segredo `FINANCEIRO_API_TOKEN` fica reservado à criação administrativa de contas e à assinatura de sessões, nunca serve como sessão de usuário. Não tratar código no GitHub como deploy concluído.
10. **Isolamento por usuário:** `registros.usuario_id` é chave estrangeira obrigatória para `usuarios.id`. Toda listagem, gráfico, criação, edição ou exclusão deve ser restrita ao usuário obtido da sessão autenticada, nunca de parâmetro do cliente. A API não deve permitir acesso apenas com chave administrativa.
11. **Login individual:** usuário + senha, com hash PBKDF2-SHA256, sal aleatório exclusivo, 600.000 iterações e sessão assinada HMAC com validade de 8 horas, guardada somente na memória da aba. Cadastro somente via endpoint administrativo com `FINANCEIRO_API_TOKEN`; não permitir autoinscrição pública. O segredo administrativo não é o login do usuário. Não publicar sem testar a separação entre contas.
12. **Visual:** dark mode sempre como padrão, sem depender do tema do sistema operacional. Aplicar a toda a interface (sidebar, cartões, gráficos, tabelas, inputs, diálogos e telas mobile). Priorizar contraste legível, cores consistentes e aparência profissional.
